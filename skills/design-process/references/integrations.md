# Other design skills

This skill owns authority, the run, the project's files and the council. Another installed skill can do one bounded job inside a phase. Record its name and version (git commit or release) in `run.md`. It never writes DESIGN.md, never chooses between directions, and its own workflow never takes over the run. None is required.

| Skill | Use it for | Keep it away from |
|---|---|---|
| impeccable (pbakaus/impeccable) | Focused audits and polish passes in refine; its `PRODUCT.md` as the product brief's source | Explore: its redesign flow reads the current look and can rewrite DESIGN.md |
| Emil Kowalski's skills (emilkowalski/skills) | Motion, component prototypes, mobile detail in refine | Choosing the direction |
| Anthropic frontend-design (anthropics/skills) | A designer's direction planning in explore | Overriding the stance or the default check |
| unslop (heydamir/unslop) | One cleanup pass in refine | Reopening a decided look |
| Stageshow (benjitaylor/skills) | Authored product demos and illustrations | Evidence that a real flow works: its interactions are simulated |
| taste-skill (Leonxlnx/taste-skill) | v2.5+: marketing and company websites only | App screens. v2.5.0 (2026-11-05) removed the app-screen route; that guidance survives only at v2.1.5 (commit `12af471`), as reading |
| tstack council (t3dotgg/tstack) | Nothing here | Running alongside this skill's council, which replaces it for design work |

The back-and-forth, code-loop and see-it-through skills keep their own procedures: invoke them, don't restate them.

# Refine

Develops the picked direction, or changes an existing UI, driven by the user's reactions. No council runs during refine.

Record each reaction first (SKILL.md). Then pick the smallest response that resolves it:

- **A local visual change** (size, spacing, position, colour, cutting copy): make it yourself now, recapture the affected cases, and show before and after.
- **The user is unsure** ("give me options", "something's off but I don't know what"), or the fix has several honest answers:
  1. Build 3–6 variants of that one element on the real screen, behind a variant switch, each a different structure rather than a recolour.
  2. Capture a comparison sheet at every viewport and show it numbered.
  3. After the user picks, keep the pick and delete the other variants.

  Offer variants instead of a round of questions.
- **A structural or behavioural change** (a new layout, a new component, data flow): make it, keeping to the relevant decisions and craft.md. Review the change with the code-loop skill when it changes code beyond styling and the user has named a model for it.

When a change would contradict a recorded decision, ask before making it.

Done when the user says the look is settled (go to the council) or stops for now. Either way, every reaction has its row.
